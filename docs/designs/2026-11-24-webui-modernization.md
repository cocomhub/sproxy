# Web UI 现代化：现状诊断、三套方案与设计规范

- 日期：2026-11-24
- 状态：设计稿（待选型）
- 原型：`docs/designs/mockups/webui-v2-prototype.html`（浏览器直接打开；右下角「设计稿」可切换 A/B/C、亮/暗、密度；支持 `⌘K`、行选择、详情抽屉）
- 相关：`docs/designs/2026-11-21-cloud-download-visibility-and-retry.md`、`web/static/style.css`、`web/e2e/`

## 0. 结论摘要

| 项 | 结论 |
| --- | --- |
| 问题定位 | 不是「配色难看」，而是**没有设计系统**：token 三份重复、内联样式 700+ 处、无键盘模型、无焦点/动效/数字排版规范 |
| 三套方案 | **A 工程控制台**（深色优先 + 侧栏路由 + ⌘K，现代感最强、改动最大）／**B 运维仪表盘**（浅色 + KPI/水位卡片，局部改造）／**C 精修既有**（不动 IA，换 token + 组件 + 交互增强，风险最低） |
| 推荐 | **C 打底 + A 的交互内核 + B 的数据组件**（已定稿）：先拿 80% 观感与效率收益，不重排信息架构 |
| 执行方式 | **双轨并行**：旧页 `/ui/` 原样保留可用，新版落在 `/ui/v2/` 灰度；功能迁移逐项登记在 `docs/designs/webui-parity-matrix.md`，**全绿前不删旧页** |
| 硬约束 | 118 个 e2e 依赖的 `#id` 必须保留；CSP `default-src 'self'`；无构建步骤；新增 JS 必须登记 `make web-test`；UI 改动必须带 `node --test` + Playwright e2e |
| 分批 | P0 token/基础组件 → P1 文件页 → P2 传输页 → P3 控制台 → P4 键盘/命令面板/a11y，每批独立 PR 可回滚 |

## 1. 现状诊断（代码实测，非主观印象）

| 指标 | 实测值 | 影响 |
| --- | --- | --- |
| `index.html` 内联 `style="` | **137** 处 | 无法批量调主题；改一处间距要翻 HTML |
| JS 模板内联样式 | **约 610** 处 | 同形组件在不同页面观感漂移 |
| JS 中硬编码 hex 颜色 | **51** 处 | 暗色/亮色切换对这些元素失效 |
| `style.css` 变量声明 | **120** 个，但同一套 token **复制 3 份**（`:root` / `@media (prefers-color-scheme: dark)` / `[data-theme="dark"]`） | 注释已自承「需与 @media 块保持一致」——必然漂移 |
| 主容器 | `max-width: 1000px`；控制台弹窗 `1229×736` | 1440/1920 屏大量留白，表格信息密度低 |
| `font-variant-numeric: tabular-nums` | **0** 处 | 大小/时间/速率/百分比数字跳动、难对齐 |
| `:focus-visible` | **0** 处 | 键盘用户看不到焦点位置 |
| `aria-live` | **0** 处 | 上传进度、任务失败不播报 |
| `prefers-reduced-motion` | **0** 处 | 动效无法被系统偏好关闭 |
| JS 文件 / `app.js` | **63 个 / 4548 行** | 单文件过大，渲染逻辑与状态混杂 |
| e2e 依赖的不同 `#id` | **118** 个 | 任何 IA 重排都要同步改 e2e，是方案 A 的主要成本 |

**结论**：视觉债集中在「token 重复 + 内联样式 + 无组件层」；交互债集中在「无键盘模型、无命令入口、控制台是弹窗、批量操作靠顶部工具条」。

## 2. 外部调研结论（用于选型，不做风格崇拜）

1. **Linear 的主题工程**：主题在 LCH 空间生成，保证明度均匀；暗色不是纯黑（`#0A0A0A` 级），背景 → surface → raised 三级明度差；边框用 alpha 白（6–10%）而不是实色灰；数字统一 `tabular figures`；标题字距 `-0.02em`。[来源](https://linear.app/now/how-we-redesigned-the-linear-ui)
2. **深色极简栈的共识**：近黑背景 + 一级更亮的 surface + 单一强调色（Linear 靛蓝 / Raycast 橙 / Vercel 白），强调色只承担「可交互」语义。[来源](https://www.designmd.co/blog/dark-minimal-stack)
3. **数据密集后台**：列表对象（lists of objects）优先、密度可切换、状态用语义色 + 数字右对齐、筛选用 chips 而非下拉堆叠（Grafana 设计系统模板思路）。
4. **可访问性底线**：WCAG AA 正文 4.5:1、大字/图形 3:1；现有暗色按钮已按 AA 校准过，改造不得回退。

**对 sproxy 的推论**：这是「单人/小团队对自己的存储做运维」的工具，使用场景是**高频、长时间、看状态、批量操作**。因此优先级是：**密度 > 键盘效率 > 状态可读性 > 装饰性留白**；不需要营销站的留白与渐变。

## 3. 三套方案

### 方案 A：工程控制台（Engineering Console）

- **关键词**：深色优先、近黑分层、单一靛蓝 `#7C86FF`、1px 发丝边框、几乎无阴影、紧凑密度、`⌘K`。
- **信息架构**：左侧 rail（工作区 / 控制台 / 系统）+ 页面路由；**控制台从全屏弹窗改为真正的页面**；文件页右侧可拉出检查器（Inspector）。
- **界面语言**：表格 + 行内状态 pill + 行 hover 才出现的操作；批量选择后底部浮动操作条；所有数字等宽。
- **优点**：现代感与专业感最强；密度与键盘效率天然匹配；控制台多分区不再挤在 736px 弹窗里。
- **缺点/风险**：改动面最大；118 个 e2e id 需要映射表；控制台 e2e（`web/e2e/*stats*`）需重写；深色默认与现有「跟随系统」习惯冲突。
- **工作量**：L（4–5 批 PR，含 e2e 迁移）。

### 方案 B：运维仪表盘（Ops Dashboard）

- **关键词**：浅色优先、卡片化、KPI 磁贴、卷水位、筛选 chips、语义状态色（成功/警告/失败）。
- **信息架构**：不改主 IA；控制台仍在弹窗内，但内部改为「KPI 网格 + 卷水位 + 最近审计 + 待处理事项」卡片布局。
- **界面语言**：`shadow-1` 卡片、12px 圆角、进度条带阈值色（<70% 强调色 / 70–90% 警告 / >90% 危险）。
- **优点**：对「一眼看状态」最友好；改动集中在控制台内部，风险中等；对 e2e 影响小。
- **缺点**：文件页仍是传统表格，现代感一般；卡片在窄屏堆叠后很长；容易变成「仪表盘海报」而降低操作效率。
- **工作量**：M（3 批 PR）。

### 方案 C：精修既有（Refined Legacy）

- **关键词**：不动 IA、不动 DOM 结构，只做「设计系统 + 组件类 + 交互增强」。
- **做法**：
  1. token 去重为**单一定义**（亮色 `:root`，暗色只覆盖差异）；
  2. 8pt 间距、5 级字阶、4/6/8/12 圆角、两级阴影；
  3. 统一 `.btn / .field / .table / .pill / .card` 组件类，逐页把内联样式替换成类；
  4. 补 `focus-visible`、`tabular-nums`、`prefers-reduced-motion`、`aria-live`；
  5. 增加骨架屏、空态引导、浮动批量条、详情抽屉、toast 撤销。
- **优点**：风险最低，可逐页替换、逐页验证；e2e 基本不动；观感提升立竿见影。
- **缺点**：控制台仍是弹窗模式，长期架构不变；对「页面级导航」的体验提升有限。
- **工作量**：S–M（2–3 批 PR）。

### 对比

| 维度 | A 工程控制台 | B 运维仪表盘 | C 精修既有 |
| --- | --- | --- | --- |
| 观感提升 | ★★★★★ | ★★★☆☆ | ★★★★☆ |
| 操作效率提升 | ★★★★★ | ★★★☆☆ | ★★★★☆ |
| 改动风险 | 高 | 中 | 低 |
| e2e 影响 | 大（IA + 控制台） | 中（控制台内部） | 小 |
| 工期（人日，估） | 12–16 | 6–8 | 4–6 |
| 可回滚性 | 按批次 | 按批次 | 按页面 |

### 推荐路线（融合）

**C 的迁移方式 + A 的交互内核 + B 的数据组件**：

1. 先做 P0（token/组件/可访问性）——不改变任何 IA，零 e2e 风险；
2. 文件页与传输页套用 A 的密度与交互（表格 + 浮动批量条 + 检查器 + `⌘K`），但保留现有 `#id` 与 DOM 层级；
3. 控制台内部采用 B 的 KPI/水位卡片，容器是否从弹窗改页面留到 P3 单独决策（可用 A/B 试验 + e2e 对照）。

## 4. 设计系统规范（三方案共用，落地为 `tokens.css` + `components.css`）

### 4.1 颜色：只暴露语义角色

| 角色 | 用途 | 暗色建议 | 亮色建议 |
| --- | --- | --- | --- |
| `--bg` | 页面底色 | `#0A0B0E` | `#FBFBFC` |
| `--surface` | 卡片/侧栏/弹窗 | `#101216` | `#FFFFFF` |
| `--surface-2` | 表头、次级块 | `#15181D` | `#F6F7F9` |
| `--surface-3` | 输入底、进度槽 | `#1B1F26` | `#EEF0F4` |
| `--border` | 分隔线 | `rgba(255,255,255,.07)` | `#E6E8EC` |
| `--border-strong` | 输入边框、可聚焦边界 | `rgba(255,255,255,.13)` | `#D5D9E0` |
| `--text` / `--text-2` / `--text-3` | 主/次/弱文本 | `#E7E9EE` / `#9AA2AF` / `#6B7280` | `#0E1116` / `#5B6472` / `#8A93A0` |
| `--accent` / `--accent-soft` | 主操作、选中 | `#7C86FF` / 14% alpha | `#5B63E8` / 10% alpha |
| `--ok` / `--warn` / `--bad` / `--info` | 状态语义 | `#3ECF8E` / `#E5A04A` / `#F16A72` / `#5B9DFF` | `#1F9254` / `#A86400` / `#C6333C` / `#2563EB` |

规则：
- **禁止在 JS/HTML 写 hex**，只引用变量（现状 51 处需清零）；
- 状态色只表达状态，不得当装饰；
- 强调色只用于主操作与选中态；
- 暗色用 alpha 边框（更耐背景变化），亮色用实色边框。

### 4.2 排版

- 字族：`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`；等宽 `ui-monospace`。
- 字阶：11 / 12 / 13 / 14 / 20 / 26，行高 1.45；标题 `letter-spacing: -0.01em`。
- 所有数值型内容（大小、时间、速率、百分比、校验位、任务 id）**强制 `font-variant-numeric: tabular-nums`**。

### 4.3 间距 / 圆角 / 层级 / 动效

- 间距基数 4：4 / 8 / 12 / 16 / 20 / 24 / 32。
- 圆角：4（徽标）/ 6（小控件）/ 8（按钮、输入）/ 12（卡片、弹层）/ 16（对话框）。
- 层级：0 平面；1 卡片（`shadow-1`）；2 弹层（`shadow-2`）；**阴影不表达状态**。
- 焦点：统一 `0 0 0 3px` accent 22–32% alpha ring，仅 `:focus-visible`。
- 动效：120ms（hover）/ 180ms（浮层）/ 200ms（抽屉），`cubic-bezier(.2,0,.2,1)`；`prefers-reduced-motion: reduce` 全禁用。
- 密度：`compact` 行高 36 / `comfortable` 46，存 `localStorage`。

### 4.4 状态与反馈

- 状态 pill 四类：`ok / warn / bad / info`，带 6px 圆点，不使用纯色底块。
- 进度条按阈值变色：<70% accent，70–90% warn，>90% bad；**失败态显示原因分类**（`content_mismatch` / `target_unavailable` …）而不是 `error`。
- 所有异步结果走 toast（成功 3s，失败常驻可关闭），破坏性操作提供撤销窗口。
- `aria-live="polite"` 播报：上传完成、任务失败、校验结果。

### 4.5 结构轴参数化（原型实测，避免“只换颜色”）

三套方案必须能在**灰度截图**下区分；仅颜色不同不算差异。原型 `webui-v2-prototype.html` 的结构实测：

| 结构轴 | A 工程控制台 | B 运维仪表盘 | C 精修既有 |
| --- | --- | --- | --- |
| 导航 | 左侧 rail 212px | 左侧 rail 236px | **顶部 tab（无 rail）** |
| 控制台容器 | `static`（页面内） | `fixed` 弹窗 1180×760 | `fixed` 弹窗 1229×736 |
| 表格行高（实测） | **35px** | 45px | 57px |
| 卡片圆角 | 8px | **12px** | 8px |
| 卡片阴影 | **none**（仅 1px 边框） | shadow-1 | shadow-1 |
| 正文/按钮 | 13px / 30px | 13.5px / 34px | 14px / 34px |
| 批量操作 | 底部浮动条 | 卡片顶栏 | 现状黄色条 |
| 数据表达 | 行内细进度 + 迷你柱 | KPI 大卡 + 阈值仪表 | 汇总条 + 表格 |

验证方式：`--window-size=1500,950` 各截一张图转灰度后比较像素差（A/B/C 两两约 7–10%，控制台视图 A vs B/C 约 45%），且用结构探针读取 `rail display / row height / radius / shadow / console position` 五项必须不同。

## 5. 关键界面重设计（可在原型中逐屏查看）

### 5.1 文件页

| 现状问题 | 重设计 |
| --- | --- |
| 顶部工具条 12+ 按钮平铺，主次不分 | 主操作「上传」独立成主按钮；刷新/排序降级为图标按钮；语言/主题/回收站收进设置菜单 |
| 批量操作靠顶部黄条 | 选中后**底部浮动条**（计数 + 下载/移动/校验/删除 + 取消），不挤压列表 |
| 无文件详情入口 | 行内「详情」打开右侧检查器：卷、大小、sha256、分块、来源、版本列表 |
| 空目录只有「加载中/空」 | 空态 + 拖拽上传引导 + 「新建目录」直达 |
| 数字不齐 | 大小/时间右对齐 + `tabular-nums` |
| 面包屑不可点 | 面包屑每级可点，路径深链可分享 |

### 5.2 传输页

| 现状问题 | 重设计 |
| --- | --- |
| 任务与上传混排，状态靠文字 | 顶部 chips：全部/进行中/已完成/失败（带计数）；失败项「一键重试（换源）」 |
| 进度只有百分比 | 百分比 + 速率 + 剩余时间 + 已传/总量；失败显示诊断分类与期望/实际校验 |
| 无汇总 | 右栏：近 1 小时转存量 mini 柱图、成功/失败计数、平均速率、操作审计流 |

### 5.3 控制台 · 概览

| 现状问题 | 重设计 |
| --- | --- |
| 弹窗内 10 个分区横向挤压 | 左栏分区导航（统计/云端任务/待处理/审计/卷/凭据/Secret/同步），保留可键盘跳转 |
| 只有数字表格 | 首屏 4 张 KPI（任务/失败/水位/待处理）+ 卷水位条（含副本与策略足迹说明） |
| 失败不可下钻 | KPI 可点击深链到「云端任务 · 失败」筛选态 |

### 6.1 交互规范（v3 定稿，实现时按此对齐）

**导航层级（2026-11-24 修正）**
- 侧栏只保留**一个**「控制台」入口；12 个分区导航只存在于控制台内部（`.cnav`），不再在侧栏重复；
- 容器入口（控制台）在打开时只加 `data-open` 弱提示，**不设 `aria-current`**；当前态只留给内部当前分区，避免「父 + 子」双高亮；
- 手机端统一使用底部导航（文件/传输/回收站/控制台），顶部 tab 一律隐藏（含 C 方案的高特异性规则）；
- 同一目的地存在多个入口（侧栏/顶部 tab/底部导航）时，同一时刻只允许一个可见 `aria-current`。

**层级与焦点**
- 浮层栈固定为：`cmdk → help → drawer/task-drawer → console`；`Esc` 只关最上层，关闭后焦点回到触发元素；
- 命令面板 / 弹窗打开时焦点进入内部首个可操作项；`Tab` 在弹窗内循环（实现时用 focus trap）；
- 列表行 `tabindex=0`，`j/k` 用可见焦点环（`inset 2px accent`），不做隐式焦点。

**反馈分级**
| 场景 | 反馈 | 时长/位置 |
| --- | --- | --- |
| 轻量成功（复制/刷新/暂停） | toast ok | 4.2s，右下 |
| 破坏性操作（删除/取消/清空） | toast ok + 撤销 | 7s，撤销可回滚 |
| 可重试失败（校验不一致） | 行内 pill + 详情抽屉 + 重试按钮 | 常驻直到处理 |
| 页面级问题（配置校验/卷异常） | banner（带主行动） | 常驻 |
| 加载中 | 骨架屏（保持行高） | 直到数据到达 |
| 空结果 | 空态 + 一个明确动作 | 常驻 |

**危险操作规范**
- 适用范围：删除卷、封印 Secret 卷、轮换主密钥/凭据、传播删除、断开/移除节点；
- 仅卷删除与封印要求**输入名称确认**（名称不匹配则确认按钮保持 disabled），其余用红色确认按钮 + 影响说明；
- 确认框必须写清「影响范围 + 能否撤销」；不能撤销的不得提供「撤销」toast；
- 确认框在浮层栈中位于最顶层之上（`Esc` 先关它），关闭后焦点回到触发按钮。

**文案规则**
- 失败不写 `error`，写**可诊断分类**：`content_mismatch` / `target_unavailable` / `chunk_missing`；
- 每个失败必须给出「下一步动作」（换源重试 / 修复副本 / 轮换凭据 / 忽略）；
- 数字与单位分离（`4.72 GB`），时间用 `MM-DD HH:mm`，毫秒级仅用于审计。

**键盘映射（唯一事实源，实现时与 `?` 帮助共用）**
| 键 | 行为 |
| --- | --- |
| `⌘K` / `/` | 命令面板（全局搜索与动作） |
| `g` `f` / `t` / `r` / `c` | 文件 / 传输 / 回收站 / 控制台 |
| `j` / `k` | 列表焦点下移 / 上移 |
| `x` | 选中/取消当前行 |
| `Enter` | 打开当前行详情 |
| `?` | 快捷键帮助 |
| `Esc` | 关闭最上层浮层 |

## 7. 工程落地约束（必须遵守）

1. **不引入前端框架与构建步骤**：保持静态资源、`CSP default-src 'self'`；CSS 拆分为 `tokens.css` + `components.css` + `pages.css`，仍走 `<link>`。
2. **token 单一定义**：亮色在 `:root`，暗色只在 `[data-theme="dark"]` 覆盖差异；**删除 `@media (prefers-color-scheme: dark)` 的第二份**，由启动脚本读系统偏好写 `data-theme`（避免三份漂移）。
3. **118 个 e2e `#id` 必须保留**；新增交互用 `data-testid`，不复用业务 id。
4. **新增 JS 必须登记 `Makefile` 的 `web-test`**（门禁 R10）；纯函数配 `node --test`。
5. **交互/渲染改动必须补 Playwright e2e**（`web/e2e`）；仅视觉 token 调整也要保留现有断言。
6. **可访问性**：AA 对比度、可见焦点、`aria-live` 播报、`prefers-reduced-motion`。
7. **性能**：列表 >500 行启用虚拟滚动；图片 `loading="lazy"`；避免整表 `innerHTML` 重建（改为行级 patch）。
8. **禁止纯视觉 PR 不带测试**；文档与设计稿随代码 PR 合并（避免 docs-only 通道掩盖回归）。

## 11. 执行架构：双轨并行 + 功能对照门禁

### 11.1 路由与资源布局

| 路径 | 内容 | 状态 |
| --- | --- | --- |
| `/ui/` | 现有 `web/static/*`，**一行不改** | 生产可用，直到下线门禁满足 |
| `/ui/v2/` | 新增 `web/static/v2/*`（同 embed FS，独立 `tokens.css`/`components.css`） | 灰度，与旧页共用同一套 JSON API |
| `/` | 仍 301 → `/ui/`；切换入口在旧页顶栏「试用新版」 | 可逆，随时移除 |

实现要点：
- `pkg/server/routes.go` 增加一个 `GET /ui/v2/` 静态挂载（复用现有 `fs.Sub(web.StaticFS, "static/v2")`），CSP 保持一致；
- v2 **不 import 旧脚本**、不共享 DOM id（避免两套逻辑互相污染）；
- 旧页仅新增一个入口链接（可回滚）；**不做默认跳转**，直到本表全绿后单独开 PR 决策。

### 11.2 功能对照门禁（本次新增的唯一门禁，替代“凭印象迁移”）

`docs/designs/webui-parity-matrix.md` 是迁移进度的**唯一事实源**：

1. 每个 PR 必须更新受影响行（状态 + 证据）；CI 不自动校验表格，但 PR 模板/评审检查项要求附「本 PR 迁移了哪几行」；
2. `DONE` = 功能可用；`VERIFIED` = 有 `web/e2e` 或 `node --test` 证据且实测通过；
3. 旧页删除条件是显式硬门禁（0 行未完成 + 一个发布周期无 P0/P1 + e2e 已迁移 + 文档记录）；
4. 新增能力（旧版没有的，如 `⌘K`）不进对照表，避免把“新功能未做”误判为“功能遗失”。

### 11.3.1 现有原型与真实壳层的差异（避免误读设计稿）

原型用于**观感与交互对比**，且已按结构轴区分（不是换色稿）：

## 14. 前端代码复用与长期维护

**结论：不复制文件；按「可直接复用 / 共享层 / v2 自有」三层收敛。**

| 层 | 位置 | 规则 |
| --- | --- | --- |
| 直接复用 | `sclient/crypto.js`、`sclient/sig.js`（UMD，无 DOM 依赖） | v2 用相对路径 `<script src="../sclient/...">` 加载；**禁止复制** |
| 共享层（单一事实源） | `web/static/shared/{format,creds}.js` | 新共享逻辑只准进这里；UMD（浏览器全局 + Node require）；必须配 `node --test` |
| v2 自有 | `web/static/v2/*` | 只放视图/壳层/交互；不得反向 import `app.js` |
| 不可复用 | `web/static/app.js`（4.5k 行 DOM 耦合） | 不引入；旧页下线时随页面一起删 |

**已知重复与收编计划**：

| 重复项 | 现状 | 计划 |
| --- | --- | --- |
| `formatSize` | 旧页 `app-render.js` / `quota-format.js` / `user-volumes.js` 各一份（精度/上限不同） | v2 统一用 `shared/format.js`；旧页保留到下线批次一次性换实现（避免改旧页显示精度与快照） |
| 凭据存储键名 | 旧页 `app.js` 硬编码 3 个 sessionStorage 键 | 键名作为**契约**收敛在 `shared/creds.js`；旧页保持写入端不变（P1a 已验证同源可读） |
| i18n 词条 | 设计稿 331 条为原型数据；旧页有 `i18n.js` | 落地时以旧页 `i18n.js` 为词条源，v2 复用其 `t()`，不另造字典 |

**依赖方向**：`shared ← v2`、`shared ← legacy`；`shared` 不 import 任何页面模块；加载顺序在 HTML 中显式声明（无打包器）。

**下线路径**：parity 表全绿 → 删除 `web/static/*`（旧页）→ `shared/` 保留并成为唯一来源；本设计稿原型目录不参与构建，不进入运行期。
