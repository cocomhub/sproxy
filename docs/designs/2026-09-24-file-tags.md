# 文件标签系统（11.10-④）

## 背景/目标
- 现状：`pkg/files/search_index.go` 的 `indexEntry` 只有 `base`（名字子串）与 `contentTokens`（内容抽样词元）两种匹配维度，无结构化标签能力；搜索 `GET /api/files/search?q=` 只走这两个字段。
- 目标：新增 `POST /api/tags` 打标（支持批量），搜索/列表按标签过滤（`tag=` 参数）；标签随索引快照持久化、重启不丢；打标/搜索不影响既有语义。

## 组件与接口
- `pkg/files`：
  - `indexEntry` 新增 `tags []string` 字段（与 contentTokens 并存，互不干扰）。
  - `Service.TagFiles(owner string, rels []string, tags []string) error`：写路径增量——复用 `cloneOwnerIndexLocked` copy-on-write，新增 `setTagsLocked(oi, rel, tags)` 后替换 `ix.owners[owner]` 指针（与 upsert/rename 同并发模型）。
  - `Service.SearchTagged(owner, q, tag string) []FileInfo`：`searchLocked` 增加匹配分支——`tag` 非空时要求 `e.tags` 含该标签（精确/子串二选一，设计定精确匹配 + `q` 仍走 base/contentTokens）。
  - 持久化：新增 `tagsStore`（meta 桶 `<owner>/meta/tags/<sha256(rel)>.json`，单文件原子写）；`walkUserRoot` 构建时载入合并进 `indexEntry.tags`。**快照序列化需同步带 tags 字段**（loadIndexSnapshot/saveIndexSnapshot 所在文件未在本批阅读范围，落地时核对编码并版本化）。
- `pkg/server`：
  - `POST /api/tags?filename=<name>&tags=a,b,c`（JSON body 支持 `{files: [...], tags: [...]}` 批量）；返回打标结果。
  - `GET /api/files/search?q=&tag=` 增加 `tag` 过滤参数（与 q 可组合）。
- 校验规则：标签 `[A-Za-z0-9_\p{L}-]{1,32}`，每文件 ≤20 个，自动去重排序。

## 数据流
打标请求 → auth → handler 校验（文件存在性 + 标签合法）→ tagsStore 原子写（成功才继续）→ `index.setTags`（COW 替换指针）→ 后续 `search?tag=` 命中；rename/delete 沿既有 rename/remove 路径顺带搬移/删除标签（tagsStore 同更新）；索引失效重建时从 tagsStore 重新合并。

## 错误处理
文件不存在 → 404；标签非法/超量 → 400（整批拒绝，不部分成功）；tagsStore 写失败 → 500 且索引不更新（索引只是缓存，下次构建以 store 为准）；旧格式快照缺 tags 字段 → 按 nil 处理（零回归）。

## 测试+变异点
- handler 打标/搜索/批量/校验 table-driven 单测；`setTags` COW 并发读（reader 遍历旧 map）不 panic、无 race（`-race`）；快照含 tags 往返。
- 变异验证：① search 忽略 tags 分支 → tag 搜索测试红；② setTags 原地改 entry（非 COW）→ race 测试红；③ 打标失败仍更新索引 → 红。

## 片划分
- 片1：tagsStore + `indexEntry.tags` + setTags/search 分支（纯 pkg/files 单测 + 快照兼容）。
- 片2：`/api/tags` + `search?tag=` handler 接线 + docs/config.md、docs/api.md。

## 风险与零回归
- 空标签/未启用 → 逐字旧行为（golden 测试锁定）；快照格式变更需兼容旧快照（缺字段默认 nil）；内存成本每文件 ≤20 字符串，受上限约束；不动 checksum 台账与 contentTokens 语义。
