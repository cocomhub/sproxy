# 设计：OIDC / LDAP 外部认证（auth.oidc + auth.ldap）

## 背景与目标

现状（源码事实）：`pkg/server/auth.go` 认证链为 Authenticator 插件链（DEC-C，
`Authenticator` 接口：`Name()` + `Authenticate(ctx, r) (*Principal, error)`），
`RingAuthenticator` 是默认实现（SproxySig 验签）；`register_handler.go` 的 register
是唯一用户入口（简单 AK/SK 或 TOTP 分支，`AddRegistration` 原子授首 admin）；
`accesskey/storer.go` 的 `CredentialStorer`（Load/Save）是凭据 Ring 持久化抽象
（宿主可注入 KMS 实现）。无任何外部身份源。

目标：
- `auth.oidc: {issuer, client_id, client_secret, redirect_url}` — OIDC 登录
  （Authorization Code + PKCE），登录成功 → 按 `sub` 建立/映射本地凭据（owner）；
- `auth.ldap: {url, bind_dn, base_dn}` — LDAP 绑定认证（用户名+口令）；
- 插件化：OIDC/LDAP 是**独立 go module（ext 隔离）**——OIDC 用 golang.org/x/oauth2
  （x/ 准标准库），LDAP 用 go-ldap（第三方，须 ext 隔离评审）；
- 零回归：未配置 = 不启用，认证链与注册流与现状完全一致。

## 组件与接口

1. 配置模型（`pkg/server/config.go`）：
   ```go
   type OIDCConfig struct {
       Enabled       bool   `yaml:"enabled"`        // false = 不启用（零回归）
       Issuer        string `yaml:"issuer"`         // OIDC discovery 基址（/.well-known/openid-configuration）
       ClientID      string `yaml:"client_id"`
       ClientSecret  string `yaml:"client_secret"`
       RedirectURL   string `yaml:"redirect_url"`
       ClaimOwner    string `yaml:"claim_owner"`    // 映射 owner 的 claim（默认 email，回退 sub）
       AutoProvision bool   `yaml:"auto_provision"` // 首次登录自动建本地凭据（默认 true）
   }
   type LDAPConfig struct {
       Enabled  bool   `yaml:"enabled"`
       URL      string `yaml:"url"`      // ldap:// 或 ldaps://
       BindDN   string `yaml:"bind_dn"`  // 服务账号绑定（可空 = 匿名 search）
       BindPassword string `yaml:"bind_password"`
       BaseDN   string `yaml:"base_dn"`
       UserFilter string `yaml:"user_filter"` // 默认 (&(objectClass=inetOrgPerson)(uid={{username}}))
       UsernameAttr string `yaml:"username_attr"` // 默认 uid
   }
   type AuthExternalConfig struct {
       OIDC OIDCConfig `yaml:"oidc"`
       LDAP LDAPConfig `yaml:"ldap"`
   }
   ```
   `Config` 新增 `ExternalAuth AuthExternalConfig`（`yaml:"external_auth"`，避免与
   auth.allow_ips 段名冲突）。
2. 认证器（ext module：`pkg/tunnel/xfer/ext/…` 同款独立 go.mod 模式，建议
   `ext/oidcldap` 或拆两个 `ext/oidc`、`ext/ldap`）：
   - 实现 `server.Authenticator` 接口，注册经 `RegisterRoutesOpts.Authenticators`
     **宿主注入**（pkg/server 不 import ext module，避免包级依赖环——与
     XferMetrics/CloudExitDial 注入同构）。
   - OIDC 认证器：`Authenticate` 识别 `Authorization: Bearer <id_token>` 或会话 cookie
     （设计取 Bearer id_token 校验：`oidc.NewProvider` → `Verifier` → IDToken.Claims，
     `sub`/`aud`/`exp` 校验）→ 返回 Principal{AK: <owner 派生>, Owner, Role: "user",
     Mesh: ""}。**AK 用稳定 owner 名**（如 `oidc:<sub>` 归一），按既有按 AK 落桶语义落
     owner 桶；无 SproxySig SK → Secret 空 → /tunnel 不可用（文档明示：OIDC 身份走
     直连 HTTP 面，不建立加密隧道）。
   - 登录页/授权码交换：新增公开端点（主 mux + localMux）：
     `GET /auth/oidc/login`（跳转 issuer 授权 + PKCE state/verifier 存服务端内存表）→
     `GET /auth/oidc/callback`（换 token、验 id_token、映射/建凭据、发会话 cookie）。
     session 由服务端签发短命 Bearer（复用现有 session SK 思路：签发 KindTOTPWrap 同款
     短命条目，或独立会话 cookie——设计取独立 signed cookie + 内存表，避免污染 SK Ring）。
   - LDAP 认证器：`Authenticate` 识别 `Authorization: Bearer <session>` 的换取端点
     `POST /auth/ldap/login {username, password}`：服务账号 bind → 按 UserFilter
     search 用户 DN → 用户 DN bind 验证口令（go-ldap `ldap.DialURL` + `Bind`）→
     成功返回 Principal（同 OIDC 的 owner 映射）。go-ldap 是**唯一第三方依赖**，
     ext module 隔离（核心库零新依赖）。
3. 凭据映射（`accesskey` 域）：
   - AutoProvision：登录成功 → `ring.OwnerAK(owner)` 不存在 → `AddRegistration`（RoleUser，
     无 SK/TOTP——设计新增「外部身份账号」形态：`Key` 带 Role=user、TOTPSecret=nil、
     Entries 空，仅作 owner 锚；或复用 `POST /api/credentials` 的 admin 建号路径）。
     首外部登录是否授 admin：**不授**（首 admin 仍仅限回环 register，红线不变）；
   - 已存在 owner → 直接登录（映射到既有账号）。
4. 装配：`cmd/sproxy` 按 cfg.ExternalAuth 装配 ext authenticator 注入
   `RegisterRoutesOpts.Authenticators`（默认链 + 外部链 append）；未配置 → nil（零回归）。

## 数据流

1. OIDC：用户 GET /auth/oidc/login → 302 issuer（PKCE）→ issuer 回调
   /auth/oidc/callback → code+verifier 换 token → 验 id_token（iss/aud/exp/sub）→
   OwnerAK 查/建 → 发会话 cookie → 后续请求 Bearer cookie 由 OIDC authenticator 验签。
2. LDAP：POST /auth/ldap/login → 服务账号 search → 用户 bind → 建会话（同上）→ 后续请求
   Bearer 会话。
3. 认证链：authMiddleware 先 api_keys → 再 Authenticator 链（RingAuthenticator 在
   前、外部 authenticator 在后——外部凭据格式（Bearer）与 SproxySig 互斥，先后无冲突）→
   Principal 入 ctx → fileRoute 按 Role=user 正常放行。

## 错误处理

- OIDC：state 不匹配 / code 交换失败 / id_token 验签失败（iss/aud/exp/非ce）→
  401 + 审计（credential_login_denied 同款）；discovery 失败 → 启动时 Warn + 该认证器
  停用（fail-closed：不静默降级为匿名）。
- LDAP：bind/search 失败 → 401（不泄露账号存在性，与 TOTP login 同款统一文案）；
  ldaps 证书校验失败 → 拒绝（InsecureSkipVerify 不提供，或仅显式配置开发开关）。
- 会话 cookie 过期/伪造 → 401 → 前端重新走 /auth/*/login。
- 外部认证器内部错误（网络/超时）→ 返回 error（认证链继续尝试其它成员，R4-I3），
  全失败由 authMiddleware 统一 401——**不因外部源抖动把合法本地用户锁死**。

## 测试 + 变异点

- 测试（ext module 内，mock 外部源）：
  1. OIDC：httptest mock issuer（/.well-known + token + JWKS）→ 授权码换 token →
     id_token 校验通过 → Principal owner 正确；AutoProvision 建号/已有号映射两路径；
  2. OIDC 失败面：state 不匹配 / exp 过期 / aud 错 → 401；
  3. LDAP：httptest/mock ldap server（go-ldap 的 test server 或注入 Dialer）→
     bind 成功 → 建会话；口令错 → 401；用户不存在 → 401；
  4. 未配置 → 外部端点 404、认证链无外部成员（零回归断言）。
- 变异点（改后必红）：① 不验 aud → 测试 2 红；② AutoProvision 缺失分支 → 测试 1 红；
  ③ LDAP 成功路径不建会话 → 测试 3 红；④ 外部 authenticator 写响应短路链 →
  链语义测试红（R4-I3 回归）。

## 片划分

- 片 1：ext/oidc module（x/oauth2 依赖）+ 会话 cookie 基础设施 + mock issuer 测试与
  变异验证 + 装配注入（cmd/sproxy）。
- 片 2：ext/ldap module（go-ldap 依赖评审 + ext 隔离）+ mock LDAP 测试 + 装配注入。
- 片 3：凭据映射收尾（AutoProvision/owner 锚、审计、文档 docs/config.md + R15 同步）。

## 风险与零回归保证

- 零回归面：ExternalAuth 全空 → 无新端点、认证链默认链不变、凭据 Ring 不受触碰、
  register 首 admin 回环红线不变。
- 风险 1：OIDC Bearer 会话与 api_keys Bearer 语义纠缠——设计上 api_keys 链前独立
  分支优先（现状），外部会话走独立 cookie/端点，互不覆盖。
- 风险 2：外部身份无 SproxySig SK → /tunnel 不可用、renew 不可用（文档明示；如需要
  可在后续片为外部身份签发受限 SK）。
- 风险 3：go-ldap 是第三方纯 Go 库（活跃、API 稳定），经 ext module 隔离后核心库
  零新依赖；评审门槛走 AGENTS.md 第三方依赖审慎评估流程。
- 风险 4：会话 cookie 密钥管理——由配置 `external_auth.session_secret`（32B）或
  回落凭据 master key 派生，文档明示需持久化（重启不丢会话）。
