# 多副本写面限制声明（设计文档）

> 批次：D-1（11.6-④）｜状态：已落地（权威声明见 docs/deploy.md「多副本写面限制声明」节）｜日期：2026-09-24

## 背景 / 目标
- 现状：Helm chart 支持 `replicaCount` 配置（11.6-③ 已补 RollingUpdate + PDB），但**没有任何文档声明多副本下的写面语义**；`replicaCount > 1` 的用户可能误以为写面也可水平扩展。
- 目标：以**权威文档声明**「多副本 = 只读面水平扩展 + 单写主（写面仅副本 0）」——与 11.11 集群化写面唯一（写面单一权威）对齐；给出单写主的判定口径与可观测性。

## 权威声明（关键短语，供文档断言测试锚定）
> 「sproxy 多副本部署仅支持**只读面水平扩展**；**写面只有一个写主（Write Leader）**，即序号为 0 的副本（`statefulset`/`replica 0`）。写请求应只发给写主副本；其余副本仅提供读。与 11.11 集群化写面唯一（single write master）语义一致。」

## 组件与接口
- 落点：`deploy/sproxy-helm/README.md`（或 docs/ 新增 `docs/multireplica.md`，二选一，建议前者随 chart 就近）+ values.yaml 注释（replicaCount 字段上方）。
- 判定口径（写主 = 副本 0）：
  - 单副本（replicaCount=1）：唯一副本即写主，行为与现状完全一致（零回归）。
  - 多副本（replicaCount>1）：**副本序号的确定由编排层负责**——Deployment 无稳定序号，文档要求生产多副本场景使用 `StatefulSet`（副本 0 = 写主，PVC 同序挂载），或由负载均衡器（Ingress/Service）把写请求（POST/PUT/DELETE）路由到写主；helm 模板本片**不新增编排机制**（只声明语义 + 校验）。
- 可观测性：`/api/mesh/status` 现有 node 角色/地址信息可复用；文档建议写面操作失败/重定向的判定以部署拓扑为准（写主地址由编排层提供）。
- 校验（模板级）：values 增加 `writeLeader.replicaIndex: 0`（默认 0，可配）供文档/注释引用；不做运行时强制（本片仅声明）。

## 数据流（多副本读/写拓扑）
1. 读请求 → Service/Ingress → 任意副本 → 本地读面（只读 handler）→ 返回。
2. 写请求 → 负载均衡 → 仅写主副本（副本 0）→ 落 PVC（RWO 挂载在写主）→ 返回。
3. 读副本的本地写面不对外提供服务（文档声明；Helm 不强制拦截——防止绕过写主产生分叉）。

## 错误处理
- 写请求误发到读副本：文档声明该请求不被保证（结果取决于本地存储状态），**要求负载均衡层把写路由到写主**；模板提供注释样例（Ingress annotation 或 Service 端口拆分写主端口）。
- 写主故障（StatefulSet 滚动）：序号 0 的 PVC 挂载到新 Pod 0，写面恢复；滚动期间写请求按 PDB/滚动语义短暂不可写但可读（不中断读）。
- 用户忽略声明并发写多个副本：**不做运行时防护**，文档明确「违背声明产生的数据分叉不在支持范围内」——与 11.11 写面唯一约束一致。

## 测试 + 变异点（文档断言）
- 文档断言测试（archcheck 风格，扫描上述文档文件）：
  1. 含关键短语「只读面水平扩展」——**变异**：改写短语 → 红；
  2. 含关键短语「写面只有一个写主」「副本 0」——**变异**：删除/改写 → 红；
  3. 含「11.11」对齐语义短语（「与 11.11 集群化写面唯一语义一致」）——**变异**：删除 → 红；

## 风险与零回归保证
- 风险：文档声明不产生运行时约束，靠部署纪律保证——如实披露为「声明 + 负载均衡配置样例」，不假装有强制。

- 衔接：11.6-③ 的 helm 模板（RollingUpdate/PDB）与本文档配套——「不中断」只承诺读面；写面在写主单点，写主滚动期间写不可用（文档明示）。
