## 发现清单

### F1（P1，可用性）小文件上传失败后行**永久卡在「排队中」**

`uploadFiles` 的串行队列里，分块路径（`uploadChunkedFile`）自己有失败处理，但小文件路径
（`uploadSimpleFile`，`size ≤ SIMPLE_LIMIT`）只写了 `.then(done)`，**没有失败分支** ——
请求失败时行既无「失败：原因」也无「重试」，`data-state` 停在 `running` 而文案仍是「排队中…」，
队列也看不到该项的真实结局。

- 影响：小文件（最常见）上传失败时用户完全无法判断发生了什么、也无法原地重试。
- 修：抽出 `markFailed(item, file, err, retry)` 供两条路径共用；队列改走统一 `attempt(pair)`，
  **单文件失败不阻断后续**（`then(ok, err=>null)`）。
- 变异：把失败分支改回不处理 ⇒ e2e「小文件失败未落到 failed 态（行状态=running|…排队中…）」红。

### F2（P2，正确性/布局）窄屏卡片：操作列没跨整行

`.table.cards-narrow td:nth-child(7)` 写死列号，但三张表列数不同
（文件 7 / **云任务 6** / **回收站 3**）⇒ 云任务与回收站表的操作按钮挤在第二列，
而 `nth-child(7)` 根本不存在。

- 修：改用 `td.actions { grid-column: 1 / -1 }`（语义选择器，与列数解耦）。
- 变异：去掉该规则 ⇒ e2e「操作列未跨整行（grid-column=auto/auto）」红。

### F3（P2，可用性）上传汇总文案自相矛盾

`上传中 N 项 · 失败 M` 里的 N 取 `rows.length`（含 failed/paused/queued）⇒ 出现
「上传中 1 项 · 失败 1」（同一行既是"上传中"又是"失败"）。

- 修：按 `data-state` **分项**统计（排队 / 上传中 / 暂停 / 失败），空则「共 N 项」。
- 变异：改回旧文案 ⇒ e2e「上传汇总未分项统计失败数」红。

## 明确判为「不是缺陷」（附理由，避免后续重复报）

| 现象 | 判定 |
| --- | --- |
| `skip_confirm=true` 后服务端**仍做全部校验**（checksum/配额/权限） | 设计正确：它只关**确认框**，不是授权门 |
| `skip_confirm` 存在 `<meta>/ui/prefs.json`（跨设备生效） | 设计正确：它是**用户策略**，与"当前视口/上次点击"不同 |
| 回收站「彻底删除」也受 `skip_confirm` 影响 | 设计正确：它就是删除确认的一部分，单列例外只会让规则难记 |
| `NewSet` 的 `roots=nil` 站点仍需 `Close()` | 无害：`Set.Close()` 关不到任何句柄；登记例外避免噪声 |
| 上传仍**串行** | 设计正确：避免并抢带宽；并发属服务端 chunked 独立议题 |
