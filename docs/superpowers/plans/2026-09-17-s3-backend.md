# S3 对象存储后端（go.mod 隔离 + MinIO 容器测试） 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 实现 **S3 对象存储后端**：任意 S3 兼容存储（AWS S3 / MinIO / COS / OSS）作为 sproxy 外部卷——`sync.FS` 7 方法经 S3 API 映射，经 V3 plugin（`RegisterBackend("s3")`）接入。**独立 Go module（go.mod 隔离，用户明示）**。

**背景（用户确认 2026-09-18）：**
- ① SDK = minio-go（轻量纯 Go、API 稳定、社区活跃）
- ② 测试 = MinIO 容器（参考 vault CI 服务模式：health-cmd 就绪 + 测试检测可达 t.Skip）
- ③ go.mod 隔离（独立 module 仿 baidupcs）
- 前置：V3 plugin（master `d9e7935c`）+ WebDAV 后端（第二个外部后端实证）+ kind=volume + backend 列表 API

**架构：**
```
pkg/s3/                    # 独立 Go module（第三方 SDK 隔离）
  go.mod                   # module github.com/cocomhub/sproxy/pkg/s3
  s3_fs.go                 # S3FS：sync.FS 7 方法（minio-go 客户端）
  s3_fs_integration_test.go# MinIO 容器集成测试（S3_ENDPOINT 可达检测 t.Skip）
  backend.go               # RegisterBackend("s3") + Extra 解析
  backend_test.go

go.work 加 ./pkg/s3
主 go.mod 加 replace github.com/cocomhub/sproxy/pkg/s3 => ./pkg/s3

方法映射（S3 API）：
  ListDir(path)   → ListObjectsV2(prefix=path+"/", delimiter="/") → CommonPrefixes 目录 + Contents 文件
  Stat(path)      → HeadObject | 目录探测（占位对象或前缀）
  OpenRead(path)  → GetObject
  WriteFile(path, r, size, mtime) → PutObject
  Rename(from,to) → CopyObject + DeleteObject（S3 无 MOVE）
  Delete(path)    → DeleteObject（幂等）
  MakeDir(path)   → 零字节占位对象（key+"/"）

V3 plugin：
  RegisterBackend("s3", newS3Backend)
  v.Extra 读：endpoint/bucket/access_key/secret_key（必填）、region/use_ssl/local_root（可选）
  config volumes[] type=s3 校验

CI：
  .github/workflows/ci.yml 加 MinIO 服务（image: minio/minio + health-cmd，仿 vault）
  S3_ENDPOINT 默认 http://127.0.0.1:9000，测试不可达 t.Skip
```
