## 现场事实（已核验，供实现者直接采信，勿再自行推断）

1. **CLI 子进程必需 SproxySig 凭据**：服务端凭据 store 化后，`access_keys` 配置不再装配 Ring；`startSPROXYImpl` 通过 `seedCredentialStore(t, uploadsDir, e2eTestAK, e2eTestSK)` 在 `<storageRoot>/anonymous/meta/credentials.json` 预写 plain alive 条目（`accesskey.Key` + `SKEntry{ID: e2eTestID, Kind: accesskey.KindPlain}`）。sclient 必须带 `--access-key`/`--access-key-secret`/`--access-key-id` 三个 flag（`e2eTestAK`/`e2eTestSK`/`e2eTestID`）。
2. **CLI 走加密隧道（localMux）**：`cmd/sclient/internal/clientfactory/factory.go` 中，flag `--access-key` 非空即 `client.WithTunnel(ak, sk)`（`factory.go:212`）→ FileClient 经 `POST /tunnel` 内层 `localMux` 路由。**因此 CLI 覆盖面要求目标 handler 同时注册在 localMux**。已核验下列路由 **localMux + srvMux 双侧齐备**：`/api/versions*`（`handlers.go:765-767`）、`/api/volumes`、`/api/volumes/move`（770-771）、`/api/share`、`/api/shares*`（883-885 + 888-889）、`/api/cloud/*`（892-907 + 909-924）、`/api/stats`（771 + 876）。`GET /s/{token}` 仅 srvMux 且**无 authMiddleware**（公开，`handlers.go:880`）。
3. **sclient 全局 flag**（`cmd/sclient/root.go:107-128`，均为 PersistentFlags，可置于子命令前）：`--config`、`--server`/`-s`、`--access-key`、`--access-key-secret`、`--access-key-id`、`--volume`、`--json`、`--insecure`。`--config` 指向不存在文件时 `sclientcfg.New` 静默忽略（`sclientcfg.New`：`IsNotExist` 不报错），用于隔离本机 `~/.config/sproxy/sclient.yaml`。
4. **命令与参数（已核验）**：`upload <file...>`；`list [--subdir]`；`download <filename> [output]`；`delete <filename>`；`stat [server]`（`stat server` 查远端，其余为本地状态）；`stats`；`search <keyword>`；`mv <from> <to> [--to-volume VOL]`；`batch-rename <f1> <t1> [f2 t2 ...]`；`share create <filename> [--ttl 1h] [--max-downloads N] [--one-time]` / `share list` / `share revoke <token>`；`meta version list <filename>` / `meta version restore <filename> <version_id>` / `meta version delete <filename> <version_id>`；`cloud-download submit <url>` / `list [--status]` / `wait <id>` / `cancel <id>` / `delete <id> --yes`；`volumes`。
5. **`--json` 输出契约**（`cmd/sclient/output.go` 的 `JSONFormatter`，纯 JSON、无杂行）：`list`→`{"files":[...],"total":N}`；`search`→同 list（`PrintFileList`）；`volumes`→`{"volumes":[...]}`；`stats`/`stat server`→`client.StatsResponse`；`share list`→`{"shares":[...]}`；`share create`→`{"token","url","filename","expires_at","max_downloads","one_time"}`；`meta version list`→`{"filename":...,"versions":[{"version_id"(int64),"size","checksum","created_at"}]}`；`cloud-download list`→`{"tasks":[client.CloudTask...]}`。**`cloud-download submit` 无 JSON 输出**（直接 `WriteOutLine`），需经 `list --json` 取 task id。
6. **版本语义**（`pkg/server/version.go`）：版本在**覆盖上传**时由 `saveVersionBeforeOverwrite` 保存旧内容；`version_id` 为 int64（`time.Now().UnixNano()*1000 + rand`，**必须用 int64 字段解析 JSON，勿用 `map[string]any` 的 float64**）；`restore` 前会先备份当前文件（故 restore 后版本数 +1）；`MaxVersions>0` 时超出部分按 id 数值序删最旧。开关：`versioning.enabled: true`（缺省关闭时 list/restore/delete 均 501）。
7. **分享语义**（`pkg/server/share.go`）：`accessShareHandler` 先 `Peek` 再 `Consume`；无效/已撤销 → 404；文件已不存在 → 410；一次性链接首次访问后 `Consume` 删除 → 第二次 404；公开路由 `GET /s/{token}` 无签名可访问（裸 `http.Get`）。
8. **卷语义**（`pkg/server/config.go`）：`volumes[].root` 为空且 `i==0` 时归一为 `cfg.StorageRoot`；`resolveDefaultVolumeRoot` 因此返回 `--storage-root` 目录 → 凭据 store 仍落在 `uploadsDir`，`seedCredentialStore` 无需改路径。`acl` 缺省 `mode: deny` = **默认开放**（`config.go:363-365`）；`placement` 缺省 `prefer-default`（新文件落默认卷）。`mv --to-volume` 用 `VolumeOf` 定位源卷，跨卷走 `POST /api/volumes/move`（同 rel），目标已存在同 rel → 409。
9. **云端下载**：`startSPROXYImpl` 基础配置已含 `cloud_download_allow_private: true`，子进程可拉取本机 `httptest` 源。`submit` 提交失败（`status=="failed"`）→ 非零退出；`delete` 需 `--yes`；`cancel` 对 404 幂等返回 0。
10. **磁盘布局**：文件落 `<卷根>/<tenant>/user/<rel>`，版本落 `<卷根>/<tenant>/version/<rel>/<version_id>`，云端下载落 `<卷根>/<tenant>/cloud/<filename>`。**断言一律用 `filepath.WalkDir` 按文件名/相对片段查找，不硬编码 tenant 段**（tenant 名由凭据 Owner 推导，属实现细节）。
11. **共享二进制构建**：`e2eBinPath(t, "cmd/sclient")`（`test/e2e_relay_test.go:48`）用包级 `sync.Once` 整包只 build 一次；`startSPROXYImpl` 每次调用现场 build sproxy 到各自 tmpDir（Go build cache 命中后很快）。
12. **CI**：`e2e` job 跑 ubuntu + windows 双矩阵（`.github/workflows/ci.yml:150-169`），执行 `make test-e2e`。`GOTEST_TIMEOUT_E2E ?= -timeout=20m`（`Makefile:24`）。
13. **`make notest`（`check-ci` 成员）** 要求每个 Go 包都有 `_test.go`：**不得新增无测试的非测试包**。

`startCLIEnv` 实现要点（复用既有 helper，勿重写构建逻辑）：

```go
func startCLIEnv(t *testing.T, extraConfig string) *cliEnv {
	t.Helper()
	baseURL, storageRoot, cleanup := startSPROXYImpl(t, extraConfig)
	t.Cleanup(cleanup)
	return &cliEnv{
		BaseURL: baseURL, StorageRoot: storageRoot,
		TmpDir:     filepath.Dir(storageRoot),
		sclientBin: e2eBinPath(t, "cmd/sclient"),
	}
}
```

`sclientRun` 注入的前置 flag（顺序固定，置于子命令前）：

```go
[]string{

	"--access-key", e2eTestAK,
	"--access-key-secret", e2eTestSK,
	"--access-key-id", e2eTestID,
}
```

## 红线（所有任务通用，评审逐条核对）

1. **真二进制子进程**：所有 CLI 场景必须 `exec.Command(e.sclientBin, ...)` 跑真实 sclient 二进制；服务端为真实 sproxy 子进程。禁止 in-process 调 `cmd/sclient`（那会在 `package main` 内，也调不了）或用 FileClient 冒充 CLI 覆盖。
2. **断言真实副作用**：每条 CLI 调用后必须至少断言「磁盘文件（内容/存在性，`WalkDir` 按 basename 查找）」或「签名 HTTP API 响应（`authedHTTPClient`，checksum/状态码/JSON 字段）」之一；**不得只断言退出码或 stdout 含某字样**（负例除外，负例断言 err != nil 且无副作用）。
3. **127.0.0.1 回环**：`startSPROXYImpl`/`e2eFreePort`/`httptest.NewServer` 均绑定 127.0.0.1；禁止 `0.0.0.0`/`localhost`。
4. **纯标准库**：不引入 testify/gomega 等；断言用 `t.Fatalf`/`t.Errorf`。
5. **不新增非测试包**：避免 `make notest` 门禁失败；helper 放 `_test.go`。
6. **配置隔离**：sclient 子进程必须带 `--config <不存在路径>`，防本机用户配置渗入（memory: cli-test-config-isolation）。
7. **Windows 兼容**：路径用 `filepath.Join`/`filepath.ToSlash`；二进制名 `.exe` 由 `e2eBinPath` 处理；YAML 内路径用 `filepath.ToSlash`（反斜杠触发 YAML 转义）。
8. **`-race` 下超时留 3 倍余量**：涉及子进程/轮询的等待上限（如 cancel 轮询 10s）按正常值 3 倍给（memory: 测试超时）；`t.Parallel()` 由各用例自行决定，harness 不内建。
9. **JSON 数值精度**：`version_id`/`size` 用 int64 字段解析；禁止 `map[string]any`（float64 会丢精度）。

## `make test-e2e` 超时评估

- 现状：`-timeout=20m`，跑 `./test`（10 文件、~4041 行）在 ubuntu + windows 双矩阵 `-race`。
- 新增：5 个 CLI 用例文件（约 11 个用例）+ 孤儿用例。每用例额外成本 = 一次 sproxy 子进程启动（build cache 命中后约数百 ms）+ 若干次 sclient 子进程（每次进程启动约数十 ms）+ 云端/取消用例的网络轮询（≤10s 上限，实际 <2s）。
- 结论：**提高 `GOTEST_TIMEOUT_E2E` 到 30m**（任务 6 步骤 2）。20m 在 Windows 慢 runner 上叠加新用例有触及上限风险；30m 留足余量。若 CI 实测仍紧，再评估按用例 `t.Parallel()` 提高并发。
