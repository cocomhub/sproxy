> 日期：2026-08-30

## 功能摘要

SOCKS5 代理（RFC 1928）：`sclient socks` 启动本地 SOCKS5 代理，CONNECT 目标经 mesh
路由到指定出口节点（`--exit`），由出口节点按 dial 帧出站拨号（出口 dial 策略把关）。
同时 `mesh node --socks` 提供节点本地 SOCKS5 出口（节点本机拨号）。

## 架构决策

1. **`pkg/socks5` 与传输解耦**：`Dial`/`Auth` 注入。mesh 场景 Dial 经 mesh 到出口
   节点（目标写 dial 帧由出口拨号）；本地场景 Dial 默认 net.Dial。
2. **安全边界（对齐 mesh 网关 loopback-only + token 认证）**：
   - 监听默认 loopback（`NormalizeListenAddr`，裸 :port → 127.0.0.1:port）；LAN 暴露
     需显式通配地址。
   - 可选 RFC 1929 用户名/密码认证（`Config.Auth` / `--socks-user`/`--socks-pass`，
     配置了才要求）。
   - **SSRF 边界在出口节点 dial 策略**（`NewServiceDialPolicy`：拒绝 loopback/私网
     除非宣告为服务地址）：本地代理不直接拨任意地址。
3. **DoD 验证用官方 x/net/proxy 客户端**（`golang.org/x/net/proxy`）：标准实现验证
   服务端，比手写客户端更严谨（用户允许 x/net 系列）。
4. **mesh 路由 Dial**：`--gateway` 优先复用本地 mesh node 网关已建链路（GatewayConnect），
   回落常规拨号；`--mdns` 走直连信令（`DialDirect` + `LookupPeer` 找出口信令端点）；
   否则 hub 模式（`mesh.Dial` webrtc + relay 回落）。

## 关键坑

1. **SOCKS5 握手先回「成功」**：mesh relay 无结果帧，代理无法预知出口拨号结果，先回
   成功应答再泵送。SSRF 边界测试断言应为「CONNECT 后读返回 EOF/关闭」（目标未建立），
   而非 Dial 报错。
2. **check-loopback 误判**：`pkg/socks5` 与 `cmd/sclient/socks.go` 注释含 `0.0.0.0`
   字面量被 `make check-loopback` 扫描。改写注释（全零 IPv4 等）避免。
3. **`omitempty` 对 `time.Time` 不生效**（上个子任务教训）：Go 1.26 需 `omitzero`。

## 独立审查（对抗式）发现与修复

- **M1（必须）socks5.pump 无 grace 强制收尾 → goroutine/FD 泄漏（DoS）**：手写 pump
  无限阻塞等待两端 EOF，一端完成另一端 keep-alive 时永久持有。修复：复用
  `iostream.Pump(conn, target, iostream.PumpGrace)`（同 root module，已处理 Abort 优先
  收尾 + grace 超时强制关闭）。
- **S1（建议）relay-only 回落被 guard 阻断**：`socks.go` guard `svc==nil || signaler==nil`
  使 `--webrtc=false`/注册失败时无法走 relay-only。修复：改 `svc==nil`（signaler nil 时
  `mesh.Dial` 回落 `svc.RelayStream`）。
- **S2（建议）--socks 端口冲突导致节点崩溃/重连循环**：socks 绑定失败写 errCh 触发整
  cycle 失败。修复：Warn + 节点继续运行（对齐网关降级）。
- **S3（建议）root go.mod 引入 webrtc/pion 依赖树**：`go mod tidy` 因预存
  `webrtc_signal_e2e_test.go` 把 webrtc + pion 拉进 root go.mod。修复：还原 go.mod/go.sum
  到 master，手动仅提升 `golang.org/x/net` 为直接依赖（不跑 tidy；go.work 提供跨模块
  import）。
- **I1/I3（参考）**：nmethods==0 回 0xFF（RFC 1928 §3）；校验 RSV 字节为 0。
- **I2/I5（参考）**：Auth 用 `subtle.ConstantTimeCompare`（对齐网关）；user/pass 任一
  设置即启用认证（防只配密码被静默禁用）。

## 安全审查（后台）处理

后台安全审查指出 `pkg/socks5` 默认 Dial 无目标限制 + 无认证 = 未认证开放代理。决策：
- 加可选 RFC 1929 认证（`Config.Auth`，配置了才要求）。
- 生产 `sclient socks` 的 Dial 经 mesh 到显式 `--exit` 节点，出口 dial 策略把关目标
  （SSRF 边界）；库的裸 Dial 默认仅测试/本地出口用。
- 监听默认 loopback-only（对齐 mesh 网关）。
- 补测试：RFC 1929 三态 + `TestMeshSocks5_Exit` 的 SSRF 边界断言。
