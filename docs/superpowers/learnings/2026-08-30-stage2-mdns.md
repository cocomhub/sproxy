# 阶段 2 子任务 1：mDNS/DNS-SD 局域网发现

> 日期：2026-08-30
> 分支：`feature/mesh-p2-mdns`
> 状态：已实现 + 测试全绿 + lint 0 + 待审查/PR

## 功能摘要

纯 mDNS 无 hub 局域网发现：mesh 节点在 `_sproxy-mesh._tcp.local.` 服务类型下广播
node-id + 服务宣告 + 直连 webrtc 信令端点，同网段节点互发现；客户端经 mDNS 发现
服务后，用**直连信令**（TCP 上的 SDP offer/answer 交换，替代 hub.HubSignaler）建立
webrtc 数据面，走对端出口拨号，全程不经 hub。

## 架构决策

1. **纯 stdlib + x/net 实现 mDNS**：不用第三方 mDNS 库。`x/net/dns/dnsmessage`
   处理 DNS 报文编解码，UDP 组播 + TTL 缓存自实现。满足"核心 go.mod 零新增三方依赖"
   （mDNS 代码在 mesh 独立 module，仅新增 x/net 直接依赖，属 x/net 系列可用）。
2. **直连信令替代 hub 信令**：无 hub 时 webrtc SDP 交换经 TCP 直连对端广播的信令端点。
   协议 = `[4B BE len][JSON]`，offer 帧携带拨号方 node-id（供 accept 侧恢复身份）。
   信令握手完成后数据面独立，可关闭信令连接。
3. **发现源解耦**：mDNS 广播/浏览独立于 hub 节点列表。纯 mDNS 模式（`--mdns`）不经
   hub；未来 hub + mDNS 并存模式可在 `runNodeOnce` 内叠加 mDNS 发现环。
4. **mDNS 发现拨号用 disc- 临时身份**：对齐 hub 版 discovery，accept 侧
   `parseDiscoveryPeerID` 恢复真实 base 并注册链路（full-mesh 对称）。mDNS 局域网
   信任模型下 base 无 hub 强制校验（同网段可组播者本就可冒充任意 node-id），
   linkPool 注册仅作路由复用，非安全边界；保留半拨号序校验作纵深。

## 关键坑与修复

1. **Windows 组播回环默认关闭**：`net.ListenMulticastUDP` 在 Windows 上发送组播但收不到
   自己的回环包。Go 1.26 已移除 `UDPConn.SetMulticastLoopback`，需经 `SyscallConn` +
   平台 setsockopt（Windows `syscall` IP_MULTICAST_LOOP=11；Unix `x/sys/unix`）。
2. **Go 1.26 dnsmessage 的 TTL 在 ResourceHeader**：`TXTResource`/`AResource` 的 TTL 在
   `res.Header.TTL` 而非 body，初版引用 `b.TTL` 编译失败。
3. **`--mdns` 模式分发**：`RunNode` 初版只认 `MDNSOnly` 字段，导致测试设 `EnableMDNS`
   未设 `MDNSOnly` 时误走 hub 路径（空 hub 重连循环，mDNS 永不启动）。修复为
   `MDNSOnly || (EnableMDNS && 无 hub)` 双条件分发。
4. **check-loopback 误判**：源码出现 `"0.0.0.0"` 字面量（通配 host 比较）被
   `make check-loopback` 扫描为不安全监听。改用 `net.IPv4zero.String()` 比较并避免
   注释含该字面量。
5. **test-cover E2E 在本机 Windows 预存失败**：`TestE2E_MeshNode_ServiceAccess` 在
   干净 master 同样失败（网关 18085 超时 + 出口泵送瞬断），为 Windows 环境 flake，
   CI（Linux）正常，非本子任务回归。
6. **写后即关竞态**：webrtc 测试监听侧写完立即关闭会让拨号侧读到 SCTP abort，用二次
   握手（拨号侧回 "bye"）消除竞态。

## 独立审查（对抗式）发现与修复

审查 agent 实证复现了 F1（畸形 TCP 连接杀整节点）、发现 F2（信令端口绑全接口 + 无认证
远程可达）。已全部修复并补回归测试：

- **F1（必须修复）**：直连信令端口收到空/畸形 TCP 连接（端口扫描/curl 误连）即让
  `runWebRTCAcceptLoop` 判死、整节点退出（远程可用性 DoS）。修复：
  1. 新增哨兵 `errDirectSignalConn`，`WaitOffer` 对连接级读/解析错误只关闭该连接并
     返回该哨兵；
  2. `runWebRTCAcceptLoop` 把 `errDirectSignalConn` 与 `ErrNoIncomingConnection` 同样
     视为 per-connection 瞬时失败 → 继续监听；
  3. `WaitOffer` 改为 ctx 感知读（goroutine + select），节点关停时不被 30s 读阻塞；
  4. `WaitOffer` 开始前关闭上一次未 `SendAnswer` 的遗留连接（防 FD 泄漏）。
  回归测试：`TestDirectSignaler_MalformedConnNonFatal`（空连 + 畸形帧 + 后续正常
  offer/answer 仍成功）；`TestMeshNodeMDNS_Connect` 内插端口扫描 + 畸形帧步骤。
- **F2（必须修复）**：信令端口默认绑 `:0`（全接口）但只广播一个 LAN IP，暴露面与广播
  不一致 → 任何可路由主机可远程触发 F1 / 借 `--dial-allow` 节点出站。修复：
  `resolveSignalListenAddr` 把通配 host（空/全零/IPv6 通配）收敛到主局域网 IPv4，
  `runNodeMDNSOnly` 据此绑定具体 IP，使暴露面 = 广播的 saddr（不绑全接口）。
- **S1**：`mesh connect --mdns` 遍历所有宣告该服务的节点逐个尝试（首个失败继续）。
- **S3**：mDNS 自动对等发现环受 `cfg.Discover` 控制（`--discover=false --mdns` 不再
  自动拨号对端）。
- **S5**：`applyTXT` 无条件替换服务列表（节点删/换服务后对端缓存立即反映，不再残留
  至 TTL 过期）。

## 自动化安全审查（两轮）确认 + 修复

后台安全审查（同一 plugin 两轮）共提出 4 条 MEDIUM，统一评估与处理：

- **A/C（未认证直连信令 / egress proxy，必须处理）→ 修复**：新增**可选共享密钥
  `--mdns-secret`**。配置后：
  - 直连信令 offer 帧携带 `sig=HMAC-SHA256(secret, node+"\n"+sdp)`，listener 校验
    （`direct_signal.go` `WaitOffer`）；未授权/错误签名 offer 拒绝（非致命，防未授权
    peer 借本节点作中继/出口）。
  - mDNS TXT 宣告携带 `sig=HMAC-SHA256(secret, node|saddr|services)`，浏览方校验
    （`mdns.go` `applyTXT`）；签名不匹配/缺失的对端忽略（防广告伪造/MITM）。
  - 默认（未配置密钥）= **LAN 信任模型**：任何同网段节点可参与，出口由既有
    `dial-allow`/`dial-allow-cidr`/宣告服务地址策略约束（非开放代理）。文档化该
    边界，`--mdns-secret` 是同 mesh 节点的 opt-in 加固。
- **B（mDNS SignalAddr 未校验 / SSRF，必须处理）→ 修复**：新增导出
  `ValidateSignalAddr`，拒绝 loopback/link-local（含 169.254.169.254 云 metadata）/
  multicast/unspecified/非法端口；hostname 解析并校验全部结果。在
  `dialPeerDirect`（auto-dial）与 `runMDNSConnect`（CLI）两处共用。测试
  `TestValidateSignalAddr` 覆盖 SSRF 场景。
- **D（未认证 mDNS 服务发现伪造）→ 修复（与 A 合并）**：`--mdns-secret` 时 TXT 带
  HMAC 签名，浏览方校验，防伪造/MITM。`TestMDNSSecretAuth` 覆盖正确/错误/无密钥三态。
- **C 的「listener 默认绑 loopback」子项 → 不适用**：mDNS DoD 要求同网段节点互发现
  直连，默认绑 loopback 会使跨机发现失效。改为：默认绑主局域网 IP（暴露面 = 广播
  saddr，F2 已收敛），加 `--mdns-secret` 认证 + dial-allow 出口边界。Windows 防火墙
  对 LAN 监听弹窗是预期行为（flag 帮助已说明）。

回归测试：`TestDirectSignaler_SecretAuth`（无/错/正确签名三态）、`TestValidateSignalAddr`、
`TestMDNSSecretAuth`。均为确定性单测，不依赖组播。

**密钥机制决策（用户问询：独立实现 vs 复用 AK/SK）**：`--mdns-secret` 与 AK/SK 语义
重合（都是 mesh 级共享密钥 + HMAC 证明成员身份）。采纳**复用 AK/SK（SK）**：密钥解析
`resolveMDNSSecret` = `--mdns-secret` 优先 > `access_key_secret`（配置的 SK）> 空（LAN
信任）。hub mesh 已有 AK/SK 自动获得 mDNS 签名认证（零新增配置）；纯 LAN 用户可显式
`--mdns-secret` 或保持 LAN 信任。两个 HMAC 加**协议域前缀**（`sproxy-mdns-signal/v1`、
`sproxy-mdns-txt/v1`），复用 SK 时与 SproxySig 请求签名隔离（防跨协议混淆）。

## Windows 防火墙弹窗收敛（用户反馈）

`mesh.test` / `sclient.test` 的 mDNS 组播绑定非 loopback 接口会触发 Windows 防火墙
弹窗。修复：新增 `SetMDNSLoopbackOnly(bool)` 测试钩子（对齐 `icecfg.LoopbackOnly`），
`MDNSServer.Start` 在开启时把组播加入 **loopback 接口**（不触非本机接口 → 不弹窗）。
所有含组播的测试（`TestMDNSDiscovery_TwoNodes`/`TestMDNSLookupService`/
`TestMeshNodeMDNS_Connect`/`TestMeshNodeMDNS_MutualDiscovery`/`TestMeshConnect_MDNSDispatch`）
开头调用 `testMDNSLoopback(t)` / `mesh.SetMDNSLoopbackOnly(true)`。生产 `mesh node --mdns`
的 LAN 监听与组播弹窗是合理预期（flag 帮助已说明）。

## 已知限制（文档化，非本子任务缺陷）

- **多网卡/虚拟网卡**：`lanIPv4Addrs()` 取排序第一个作为广播/绑定地址，VPN/虚拟网卡
  环境可能广播不可达地址；可用 `--signal-addr <具体IP>:0` 显式指定（flag 帮助已说明）。
- **IPv6/无 IPv4**：mDNS 目前仅 IPv4，无 LAN IPv4 时 `mesh node --mdns` 启动失败（错误
  信息清晰）。
- **实例标签 63 字节截断**：node-id 前 63 字节相同的两个节点会共享同一 mDNS 实例标签
  （缓存互相覆盖）；node-id 需在 mesh 内唯一（与 hub 版要求一致）。
