# 阶段 2 子任务 2：DHT 接线 ext/kad → hub.DHTRegistry

> 日期：2026-08-30
> 分支：`feature/mesh-p2-dht`
> 状态：已实现 + 测试全绿 + lint 0 + 待审查/PR

## 功能摘要

把死代码 `ext/kad`（独立 go.mod 的 Kademlia 实现，实现 `hub.DHT` 接口）接线进
`hub.DHTRegistry` 插件注册表，并让 hub 节点发现使用 DHT 作为候选节点来源。**路由表
仍 hub 权威；DHT 只提供候选节点/发现，不改路由表状态。**

## 架构决策

1. **DHT 只作候选节点来源**：路由表（`MeshRouteTable`）仍权威（转发/信令/持久化）。
   注册时把节点喂入 DHT（`PeerInfo` 带 mesh 标注），`/api/hub/nodes` 发现端点把 DHT
   候选合并进结果（按 mesh 过滤 + 去重，路由表优先）。满足「路由表仍 hub 权威；DHT
   只提供候选节点/发现，不改状态」。
2. **默认不启用**：`HubServer.dht`/`Handlers.dht` 默认 nil（既有行为不变）；仅
   `hub.dht: kad` 时由 root.go 注入。测试隔离：注入用显式 `SetDHT`，不依赖全局
   `DHTRegistry.Active()`（避免共享单例污染）。
3. **ext/kad 留在独立 go.mod**：cmd/sproxy（独立 module）import ext/kad（独立 module），
   经 go.mod require + replace 接线；核心 go.mod 零新增三方依赖。
4. **100 节点压力**：内存 DHT（无界 map）全量驻留 100 节点；kad 路由表是有界 k-bucket
   （每桶 20），随机分布下部分桶满拒收（正确 Kademlia 行为），压力测试验证有界候选
   的正确性（去重 + XOR 排序 + 不 panic）。

## 关键坑

1. **kad 路由表有界**：100 节点随机 ID 分布会溢出部分 k-bucket（每桶 20，online 节点
   不淘汰），表内实际节点 < 100。初版压力测试断言「请求过多返回全部 100」失败；修正为
   验证有界候选正确性 + 把「全量驻留」放在无界内存 DHT 上验证。
2. **cmd/sproxy go mod tidy 失败**：`go mod tidy` 尝试解析 hub 包测试依赖
   （webrtctest，另一 module）失败。解决：手动加 ext/kad 的 require + replace（对齐
   ext/ws 模式），`go build`/`go test` 正常（Makefile 不跑 tidy）。
3. **DHT 喂入用显式注入**：`HubServer`/`Handlers` 默认 dht=nil（不启用），root.go 装配
   kad 时 `SetDHT` 注入；避免默认用全局 `DHTRegistry.Active()` 造成测试共享单例污染。

## 独立审查（对抗式）发现与修复

审查 agent 实证发现 2 个必须修复 + 4 个建议 + 3 个参考级缺陷，已全部处理：

- **#1（必须）mesh 隔离被破坏**：`mergeDHTNodes` 过滤条件 `cm!="" && cm!=mesh` 把默认
  mesh（`cm==""`）候选泄漏给所有 mesh 调用方（信令按 node-id 存转，可被利用跨 mesh
  拨号）。修复：严格相等 `cm != mesh`。回归测试 `TestHubNodesHandler_DHTMeshIsolation`
  （mesh-B 请求者看不到默认 mesh 候选）。
- **#2（必须）临时节点污染 DHT**：disc-/mesh-/p2p- 瞬态身份（拨号后即注销、DHT 无移除
  路径）被喂入 DHT，幽灵节点永久残留并挤占 k-bucket。修复：`isTransientNodeID` 过滤，
  只喂稳定真实节点。回归测试 `TestHubServer_SetDHT_SkipsTransientNodes` +
  `TestIsTransientNodeID`。
- **#3（建议）断开/踢出不从 DHT 移除**：`DHT` 接口新增 `Remove(ctx, nodeID)`，实现于
  memoryDHT（delete map）、KademliaDHT（kad.Remove）、mockdht；`HandleConn` 断开清理
  与 `hubRemoveNodeHandler` 踢出时调用。
- **#4（建议）dht_seeds Bootstrap 插入假 ID 幽灵节点**：多 hub DHT 组网未实现，种子
  引导会污染发现列表。修复：root.go 不再调 Bootstrap，配置预留 + 启动 Warn。
- **#5（建议）DHTRegistry 装饰性**：root.go 改为 `hub.DHTRegistry.Active()` 作为实际
  选择机制注入 HubServer/Handlers（registry 非副作用）。
- **#6（建议）hub.dht 未知值静默忽略**：config `Validate()` 拒绝非空且非 "kad" 的
  `hub.dht`。
- **#9（参考）DHT 候选 Connected 零值序列化**：`nodeResp.Connected` 加 `omitempty`。
