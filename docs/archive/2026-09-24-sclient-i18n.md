# sclient 多语言输出（i18n，11.10-⑥）— 归档

> **归档说明**：原文 `docs/designs/2026-09-24-sclient-i18n.md` 已于 2026-11-13 归档。
> 环境变量与取值规则以 `docs/cli.md`（§全局选项 ·「输出语言（i18n）」）为准（现行事实源），
> 本文件只保留**设计意图 / 取舍 / 外部契约 / 仍有效的判断**。

## 背景与意图

`TextFormatter` 的全部文案是中文硬编码，非中文环境用户体验差。目标：Text 模式文案 i18n
（默认中文**零变化**），**表格列宽与 JSON 契约不动**。

## 定案与取舍（仍有效）

1. **只翻固定文案**：列头/提示/错误前缀走字典；文件名/URL/大小/路径等**数据**原样。绝不为了 i18n
   改列宽或表格布局（否则「中英切换」变成「输出契约变化」）。
2. **JSON 模式完全不动**（`--json` 是机器契约，不进 i18n 面）。
3. **探测优先级 `LC_ALL > LC_MESSAGES > LANG`**（空跳过）——POSIX 惯例，不自造 `SPROXY_LANG`。
4. **归一与回退**：`zh*`/`C`/`POSIX`/空 → 中文；`en*` → 英文；**其它合法语言码 → 英文**（无翻译表时的
   国际通用回退）；非法形态 → 中文。
5. **缺键返回原键**（字典是纯查表）：绝不 panic、绝不返回空串（空串会把输出变成「静默缺失」）。
6. **不引入第三方 i18n 框架**：纯标准库 `map` 字典 + `fmt`，键集由测试锁「zh/en 键集合相等」。

## 外部契约

- 环境变量语义（用户可见行为）：见 `docs/cli.md`；改 locale 需重新启动命令（进程内不重读）。
- 语言代码归一形态只有 `zh-CN` / `en` 两种产物（内部实现细节，不对外承诺更多语言）。

## 落地指针

`cmd/sclient/internal/i18n/i18n.go`（`T`/`F`/`Locale`/字典）、`cmd/sclient/output.go`
（`TextFormatter` 逐处替换）、测试 `cmd/sclient/internal/i18n/i18n_test.go` 与 `cmd/sclient/output_test.go`。

## 实测差异（以代码为准）

- 设计写「`i18n.Locale` 按包级 `once` 缓存探测结果」；实现**故意不缓存**，每次调用重读环境变量——
  原因：`lookupEnv` seam + `t.Setenv` 的测试会在同一进程内互相污染（包级 once 会让环境切换失效）。
  对用户可见行为无差别（CLI 进程生命周期内环境不变）。
- 设计提的「双语 README 片段」未做（不必做文档片段即不列入口）。
