# 文件标签系统（roadmap 11.10-④）— 归档

> **归档说明**：原文 `docs/designs/2026-09-24-file-tags.md` 已于 2026-11-13 归档。
> 本文件只保留**设计意图 / 取舍 / 外部契约 / 仍有效的判断**；API 契约以 `docs/api.md` 为准，
> 实现以代码与 git 历史为准。

## 背景
搜索索引原本只有两个匹配维度：`base`（文件名子串）与 `contentTokens`（内容抽样词元），无结构化标签。
目标：打标 + 按标签过滤，且**不改变**既有三维搜索语义。

## 定案与取舍（仍有效）
1. **标签与既有维度并存互不干扰**：`tag` 走**精确匹配**，与 `q` 是 AND 关系；`q` 为空 + `tag` 非空
   合法（= 按标签列出全部文件），不退化 400。把 `tag` 做成第二个子串维度会让过滤语义含混。
2. **索引是缓存、标签 store 是权威**，写顺序固定为「store 原子写成功 → 再改索引」：
   store 写失败 ⇒ 返回 500 且**索引不更新**（宁可索引暂时陈旧，也不制造「索引有标签、重启后消失」的假象）。
3. **并发模型沿用既有 COW**：clone + `setTagsLocked` 后替换 owner 索引指针，与 upsert/rename 同模型 ——
   读侧遍历旧 map 不受影响（这是选择 COW 而非原地改 entry 的唯一理由：避免读写竞态）。
4. **校验整批拒绝**：标签非法/超量（每文件 ≤20）⇒ 400 且**不部分成功**；文件不存在 ⇒ 404 同样整批拒绝。
   部分成功会让调用方无法判断重试范围。

## 关键耦合 / 踩坑（务必保留）
- **索引快照格式与标签语义耦合**：标签随快照持久化（重启不丢）⇒ 新增字段必须**同时**改 load/save 两处，
  并让旧快照（缺字段）按 nil 处理以实现零回归；漏改 save 会出现「重启后标签全丢」的静默数据损失。
- **rename/delete 必须顺带搬移/删除 store 条目**，否则索引重建后标签会「复活」到新路径（搬移漏）或
  「悬空」在已删路径（删除漏）；索引失效重建时一律**以 store 为准**重新合并。
- 索引只是一层缓存 ⇒ 任何「索引与 store 不一致」的场景，都以 store 为真相源，不做双向回写。

## 依赖与外部契约
- 标签字符集 `[A-Za-z0-9_\p{L}-]{1,32}`（含 Unicode 字母，故非纯 ASCII 白名单）、每文件上限 20 个、
  自动去重排序 —— 该规则与错误码属对外契约（见 `docs/api.md`）。
- 存储落点是 meta 桶内的按 `sha256(rel)` 命名单文件（原子写），与 checksum 台账/内容词元互不影响。

## 落地指针
`pkg/files/tags.go`（`TagFiles` / `Service.Tags`）、`pkg/files/search_index.go`（`indexEntry.tags`、`setTags`）。
