# 通用等待/排队能力（`pkg/waitq`：加权 · 多资源 · 优先级 · 可扩展）— 归档

> **归档说明**：原文 `docs/designs/2026-10-19-waitq.md` 已于 2026-11-14 归档。
> 能力见 `AGENTS.md`（能力矩阵 `pkg/waitq`）、`docs/api.md`（`GET /api/quota` 的 `wait` 段）、
> `docs/gates.md`（R34/R36）。本文件只保留**动机 / 不变量（含修订）/ API 契约 / 裁定 / 落地指针**。

## 1. 动机
此前**没有**通用能力包，有 **4 套独立实现**：`pkg/quota/wait.go`（`WaitReserve`，`sync.Cond`）、
`pkg/quota/staging_tracker.go`（`sync.Cond` + `waitWatcher`）、`pkg/server/ratelimit.go`（计数+通道，
非阻塞）、`golang.org/x/sync/semaphore`（加权信号量，内存字节）。问题：
- **结构孪生**（#1 与 #2 是同一逻辑写两遍 ⇒ 修一处须同步另一处）；
- **丢唤醒靠调用方纪律**（登记式门禁 R34 只断言「方法体含 `withWaitLock(`」，**新增未登记入口不会被拦**）；
- **惊群**（`Broadcast` 唤醒全部等待者，只 1 个成功）；**无背压**（无队列上限）；**无可观测**（无 metrics）；
- **获取路径不收敛（两层）**：层 A 配额 `TryReserve` ~35 处 + 层 B 容量管理 `Manager.TryReserve(cat)` ~10 处，
  **等待只覆盖 1 条** ⇒ 同一「不足」在不同写面表现不同（立即失败 vs 等 30s）。

## 2. 设计原则
1. **一个通用能力包** `pkg/waitq`（加权、多资源、优先级、背压、可观测）。
2. **使用方只实现 `Resource` 适配器**（磁盘/内存/CPU/带宽/连接数）⇒ 灵活扩展。
3. **结构体能力**（`*waitq.Queue` 注入装配），**零全局可变状态** ⇒ 可测、不污染其他功能测试。
4. **锁与唤醒由能力包统一**：使用方不再手写 `sync.Cond`/广播（R36-b：禁再写 `sync.Cond`）。
5. **可测**：注入 `Clock`（`Now` + `Since`）、确定性 `Stats()`（取代 `time.Sleep` 同步）。
6. **零回归**：现有 4 套先以适配器接入（行为逐条对照），再删原实现。

## 3. API 契约（要点；完整签名见 `pkg/waitq`）
- 使用方实现 **`Resource`**：`Name()`（唯一标识，多资源排序 + 指标标签，须登记 R36-c）/`Capacity()`
  （当前可发放上限，0 = 无上限）/`Used()`（含已预留）/`TryAcquire(n)`（原子，不足 ⇒ `ErrInsufficient`）/`Release(n)`
  （**不负责唤醒**，唤醒经 `Queue.Notify`）。
- **`Queue.Acquire(ctx, Request) (*Lease, error)` 是唯一入口**；`Request{Group, N, Priority, Timeout, Label, Holder}`；
  `Lease.Release()` 幂等。`canNeverFit` ⇒ **立即失败（不排队）**；超时/ctx 打断用 `AfterFunc`（**无常驻 goroutine**）。
- **多资源**：按 `Resource.Name()` 字典序原子获取，失败按逆序回滚（无死锁）。
- **`Notify(res)` = 释放侧统一入口**（`Release` 本身不唤醒）。

## 4. 关键不变式（含**审核修订**）
- **I1 丢唤醒防护（修订：必须由释放侧配合，库不单独保证）**：原表述「使用方写错也不会丢唤醒」**不成立** ✗
  ——`pkg/quota` 的释放入口广播的是**它自己的 `root.cond`**，迁移后等待者睡在 waitq 队列上会**收不到唤醒**（更坏）。
  **修订机制**：`pkg/quota` 每个释放/放宽入口在**既有 `withWaitLock` 内追加** `queue.Notify(resource)`；
  R34 门禁断言升级为「含 `withWaitLock(` **且** 含 `Notify(`/`Adjust(`」⇒ 锁死的是**正确的队列**。
- **I2 无惊群**：唤醒时**从队首扫描**，只唤醒「当前可用额度能满足」的等待者（有界扫描 + 命中即停）。
- **I3 无忙等**：double-check 命中即返回让调用方重试（不睡）。
- **I4 无死锁**：多资源按 `Name()` 字典序获取，失败逆序回滚。
- **I5 有界**：等待者数 ≤ `MaxWaiters`；超限立即 `ErrQueueFull`（映射 429 + `Retry-After`）。
- **I6 无饿死**：优先级 + 老化（等待超 `AgeBoost` 提升有效优先级）。
- **全局锁序约定**：`waitMu → allocMu → node.mu`（根等待锁是「丢唤醒防护」的结构保证，见 quota 设计）。
