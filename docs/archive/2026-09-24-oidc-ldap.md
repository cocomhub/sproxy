# OIDC / LDAP 外部认证（auth 外部身份源）— 归档

> **归档说明**：原文 `docs/designs/2026-09-24-oidc-ldap.md` 已于 2026-11-13 归档。
> 端点与用法以 `docs/api.md`（§外部身份登录）为准（现行事实源），本文件只保留
> **设计意图 / 取舍 / 外部契约 / 仍有效的判断**。

## 背景与意图
认证链本是 `Authenticator` 插件链（`Name()` + `Authenticate(ctx, r) (*Principal, error)`），
默认实现只有 `RingAuthenticator`（SproxySig 验签），**无任何外部身份源**。目标是接入
OIDC（Authorization Code + PKCE）与 LDAP 绑定认证，且**未配置 = 不启用**，认证链与注册流
与现状逐字一致（零回归）。

## 定案与取舍（仍有效）
1. **ext module 隔离第三方依赖**：OIDC 用 `golang.org/x/oauth2`（准标准库）；LDAP 的 `go-ldap`
   是**唯一第三方**，放独立 module ⇒ 核心库零新依赖（走 AGENTS.md 第三方评审流程）。
2. **宿主注入，而非反向依赖**：ext 不 import `pkg/server`，经 `RegisterRoutesOpts.Authenticators`
   与 `authn.ExternalAuthHandler` 嵌入契约注入（与 xfer metrics / cloud exit dial 同构）。
3. **外部身份无 SproxySig SK** ⇒ 该身份**不能**用 `/tunnel` 与 SK 轮换（走直连 HTTP 面，
   不建立加密隧道）——这是刻意的边界，不是缺陷。
4. **AK 由身份稳定派生**（`oidc-<sha256(sub)[:16]>` / `ldap-<sha256(username)[:16]>`），
   按既有「按 AK 落 owner 桶」语义落桶；**首外部登录不授 admin**（首 admin 仍仅限回环 register，
   红线不变）。
5. **会话独立**：外部登录发独立 signed cookie + 内存表，**不污染 SK Ring**；`session_secret`
   未配置时回落进程内随机密钥 ⇒ **重启即全员下线**（文档明示需持久化配置）。
6. **认证链顺序安全**：`api_keys` 独立分支优先 → `RingAuthenticator` → 外部 authenticator；
   外部凭据形态（Bearer 会话）与 SproxySig 互斥，先后不影响判定；只读/写路由仍先过
   `authMiddleware`（认证不变，只在此基础上加角色判定）。

## 外部契约 / 踩坑
- `ldaps://` **严格校验证书**（不支持 `InsecureSkipVerify`）；认证失败不泄露账号存在性
  （不做「用户不存在」与「口令错」的可区分回包）。
- OIDC 取 Bearer `id_token` 校验（`iss`/`aud`/`exp`/`sub`），不引入服务端会话存储依赖。
- 配置段名用 `external_auth`（避免与既有 `auth.allow_ips` 段冲突）——改名会破坏既有配置。

## 落地指针
`pkg/authn/ext/oidcldap/{oidc.go,ldap.go,provider.go,jwks.go}`（独立 module）、
`pkg/authn/{authn.go,session.go}`（`ExternalAuthHandler` / `ExternalAuthRoute` / 会话）、
`pkg/server/config/config.go`（`ExternalAuth`、`SessionSecret`）、装配注入点 `cmd/sproxy`。
